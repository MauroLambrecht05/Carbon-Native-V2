# carbon-updater

The client-side auto-update engine and background daemon for Carbon Native desktop applications.

## Status

This daemon is **not** the updater packaged Carbon apps use. That is the Rust
updater in the runtime (`solutions/capabilities/distribution/updating/rust`).
This one is kept only until a consumer for it is confirmed or it is removed.

Its update decisions come from `@carbon/updating` and are held to the shared
conformance fixture (`solutions/contracts/update/fixtures`), so it agrees with
the other updaters about signatures, version order, rollout, the stop list,
compatibility and channels. Its local HTTP surface has not been hardened: do not
expose it beyond the local machine.

## What it is

`carbon-updater` manages the lifecycle of desktop updates inside running applications. It connects to update manifests generated by Carbon Cloud and `carbon signer`, verifies Ed25519 signatures, enforces version stop-lists, manages deterministic staged rollouts, and orchestrates atomic A/B partition swaps with automatic 3-strike crash rollback.

## Features

- **Ed25519 Signature Verification**: Cryptographically validates update manifests against public keys in `carbon.toml`.
- **Stop-List Yanking**: Prevents running versions that have been retracted due to critical security or stability bugs.
- **Deterministic Staged Rollouts**: Uses SHA-256 installation ID hashing to assign devices into stable percentage buckets (0% - 100%).
- **A/B Partition State Machine**: Atomic slot promotion (`current.toml`) with 3-strike crash detection for automatic recovery.
- **Daemon & IPC Endpoints**: Local HTTP/IPC server on port `54324` enabling frontend UI components to query update status and trigger restarts.

## Running the Updater Daemon

```sh
bun run products/carbon-updater/main.ts
```
